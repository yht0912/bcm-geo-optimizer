# Security Policy

## Supported version

Security fixes are applied to the latest released version.

## Report a vulnerability

Use GitHub's private vulnerability reporting feature when it is available for this repository. Do not disclose exploitable details in a public issue.

Include:

- affected version and file;
- impact and reproduction steps;
- the smallest safe proof of concept;
- suggested mitigation, if known.

Do not include production credentials, customer data, private session captures, or internal infrastructure details. Redact them before reporting.

## Security boundaries

The included scripts are offline aggregators. They do not make network requests, execute external commands, collect browser sessions, or store credentials. Evidence files remain the operator's responsibility and should follow an explicit retention and access policy.
